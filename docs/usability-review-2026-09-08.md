# 工廠管理 v1.1.0：操作與用詞審查

日期：2026-09-08

## 方法與範圍

以提供的手寫回饋為需求，檢查全部既有畫面、表單、項目動作、狀態提示及桌面選單；依照開檔 → 建立產線 → 建立機台 → 耗材預排 → 維護 → 編輯 → 複製 → 排序 → 重開存檔的實際工作流程驗證。

這是介面與操作流程的專家審查，包含原始碼檢查、回歸測試、Windows Electron 實際操作及截圖檢視。沒有招募受測者，沒有進行訪談、問卷或滿意度統計；不得將以下結果當成真人使用者研究。

測試皆使用獨立暫存存檔與測試設定，不修改既有工廠資料。

### 日期與複製規則

- 預定維護日期留空：依上次維護日期加週期計算；沒有上次維護紀錄時，使用建立日期。
- 預定維護日期有值：直接使用該日期作為提醒到期日，可預排，也可記錄尚未完成的過去到期項目。
- 完成今日維護：記錄今天的維護時間、清除該筆預定日期，再依週期計算下次日期。
- 日期比較使用本機日曆日，避免 UTC 跨日或日光節約時間讓提醒差一天；開著 App 跨日也會更新。
- 複製產線會連同機台與耗材一起複製；複製機台會連同耗材複製。頂層名稱加上「（副本）」。
- 副本保留描述、料號、機台資料、週期、備註，但不複製上次維護或預定維護日期，避免把原設備的維護紀錄套到新設備。介面會清楚提示此規則。
- 項目剪貼簿限本次開啟的存檔；切換存檔會清空。一般文字仍可透過系統剪貼簿與其他軟體互通。
- 現有版本 1 存檔可直接讀取。新欄位 `plannedMaintenanceDate` 為選填，讀寫時會驗證。含預排日期的存檔請用新版編輯，舊版儲存時不會保留新欄位。

## 全 App 操作舒適度審查

| 範圍 | 發現 | 已完成的改善 |
| --- | --- | --- |
| 首頁／存檔入口 | 首頁暴露 JSON、執行路徑等非必要實作說明 | 改以建立資料、繼續作業、預設資料表達；實際存檔路徑仍在工作區顯示並提供完整提示。 |
| 儲存成功／失敗 | 失敗也清掉表單，無法重試；全部表單一起重設 | 成功僅清掉提交時的那份表單；失敗保留全部輸入。錯誤提示說明下一步可檢查可寫入位置並重試。 |
| 連續作業 | 重複點擊或 Enter 可能造成重疊寫入 | 儲存鎖防止同時送出；文字欄位維持可輸入，晚到的儲存結果不會清掉新的輸入。 |
| 切換與編輯 | 耗材草稿可能跟到其他機台；編輯另一筆會無聲覆蓋草稿 | 切換父層或改編另一筆前，僅在有實際未儲存變更時提示。新增父層時若有下層草稿，保留原位置。 |
| 關閉視窗 | 未儲存變更缺少保護 | 瀏覽器離開保護與 Electron 中文離開確認；預設繼續編輯。 |
| 編輯定位 | 表單位於清單下方，按編輯後不容易找到 | 編輯後將焦點移至相應表單；欄位與表單仍保持相同 DOM 身分。 |
| 提示位置 | 頁面上方提示可能推動內容，也可能在捲動時看不到 | 工作區訊息固定在視窗角落，不推動內容；成功訊息 6 秒後消失，錯誤可手動關閉。 |
| 層級辨識 | 不易看出機台、耗材隸屬哪條產線 | 機台區顯示產線，耗材區顯示產線與機台；選取按鈕提供 `aria-pressed`。 |
| 按鈕／鍵盤 | 圖示按鈕缺乏滑鼠提示，鍵盤焦點不明顯 | 加入編輯、刪除、排序提示與明確可存取名稱；增加焦點外框及按鈕尺寸。 |
| 小視窗／縮放 | `min-width: 1100px` 導致橫向捲動 | 依寬度調整三欄、兩欄與單欄；表單和操作列可換行，長名稱及備註可折行。桌面視窗最小尺寸降低為 640 × 480。 |
| 色彩與資訊 | 到期標籤的文字色被更高優先序的通用樣式覆蓋；刪除按鈕同樣受影響 | 修正到期、即將到期、正常與刪除的語意色；仍保留文字狀態，不單靠顏色。 |
| 多行資料 | 備註的換行在顯示時被折疊 | 保留備註換行；描述及備註欄位補明確名稱，避免值變動影響自動化／輔具辨識。 |
| Windows 可攜版 | 單檔程式解壓後，預設資料可能落在暫存執行檔旁 | 依 electron-builder 啟動器原始碼提供的 `PORTABLE_EXECUTABLE_DIR` 將資料寫到原始執行檔旁。已有失敗重現與回歸測試。 |

## 驗證結果

- `npm test`：5 個測試檔案、35 項全部通過。
- `npx tsc --noEmit`：通過。
- `npm run build`：前端與 Electron 編譯通過。
- Windows v1.1.0 可攜執行檔與 ZIP 由 `npm run package:win` 產生於 `release/`。
- `TZ=America/Los_Angeles` 的維護測試：8 項通過；預設環境亦通過，涵蓋本機日曆日及閏年驗證。
- `scripts/desktop-smoke.cjs`：開發版與打包後 Windows 桌面版皆通過。使用真正的 preload → IPC → 檔案寫入，並重開驗證。
- 桌面測試涵蓋：日期持久化、耗材複製與排序、跨產線複製機台、維持選取、原生文字複製貼上、輸入焦點、儲存捲動穩定、Tab 順序、按鈕名稱。
- 四個寬度的 document scrollWidth 均未超過視窗寬度：1440、1024、768、320 px。
- 打包後頁面未觀察到 `pageerror`。
- 畫面截圖：見 [桌面工作區](screenshots/usability-1440.png)。

### 重跑桌面驗證

先讓 Playwright 可由 Node 解析（安裝於開發環境，或設定 `NODE_PATH`）。開發模式先執行 `npm run build` 與 `npm run dev:renderer`，再執行 `node scripts/desktop-smoke.cjs`。

測試已打包的 Windows 版本時，將 `FACTORY_SMOKE_EXE` 設為 `release/win-unpacked/Factory Manager Portable.exe` 的完整路徑再執行相同腳本。測試會提供獨立的預設存檔目錄與使用者設定；輸出包含暫存目錄與截圖位置。

- 已做視覺、按鈕名稱與鍵盤檢查，但未宣稱通過完整螢幕閱讀器測試或正式無障礙認證。
